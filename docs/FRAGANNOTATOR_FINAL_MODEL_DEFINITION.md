# FragAnnotator Final Model Definition

This document freezes the manuscript definition of FragAnnotator for the FragAnnotor paper.

## Decision

The main manuscript method is the fixed evidence-fusion candidate-ranking framework defined in `configs/fragannotator_manuscript_final.yaml`.

The current trained neural checkpoint is not the main method. It is retained only as audit or negative-control evidence unless a leakage-safe rerun on the same test queries and candidate sets proves that a trained neural model outperforms this frozen fixed configuration.

## Frozen Score

FragAnnotator ranks candidates by:

```text
fragannotor_casmi_adapter_score =
  clip01(
    0.65 * native_sirius_formula_score
  + 0.20 * precursor_mass_consistency
  + 0.15 * common_fragment_or_neutral_loss_formula_plausibility
  )
```

The implementation is in `scripts/run_benchmark.py`, primarily:

- `casmi_fragannotor_adapter_components`
- `mass_consistency_score`
- `formula_fragment_plausibility_score`
- `model_score`
- `write_casmi_adapter_audit`

## Components

`native_sirius_formula_score` is the native SIRIUS formula plausibility score joined to each candidate by molecular formula. This is formula evidence only. SIRIUS-derived formula or peak annotations must not be described as independently generated by FragAnnotator.

`precursor_mass_consistency` is a deterministic agreement score between the candidate formula and observed precursor m/z under the query adduct and ion mode.

`common_fragment_or_neutral_loss_formula_plausibility` is a deterministic score comparing high-intensity experimental peaks to formula-derived common fragment and neutral-loss target masses. The current implementation uses up to 40 highest-intensity peaks and square-root-scaled relative intensity weighting.

## Normalization and Missing Values

All component scores are bounded to `[0, 1]`. The weighted sum is clipped to `[0, 1]`.

Missing, unavailable, blank, or invalid numeric component values are treated as `0.0`. Missing native SIRIUS formula evidence is therefore absence of evidence, not a positive score.

## Candidate and Query Policy

CASMI2022 candidates are taken from `data/proc/casmi_2022/cand_df.pkl` under the existing benchmark protocol. The authentic structure is inserted into a query candidate set if absent before scoring. No manuscript analysis may select candidates using test labels.

Section 3.1 uses the largest protocol-consistent CASMI2022 FragAnnotator-only set, currently 229 queries. Section 3.2 must use a matched supported comparison manifest, currently expected to be the 170 CFM-ID-supported `[M+H]+` queries after manifest freeze. Ablations must use one shared query set for all variants.

## Ranking and Reproducibility

Candidates are ranked by descending `fragannotor_casmi_adapter_score` using the deterministic ordering in the benchmark evaluator. There is no stochastic model component and no learned checkpoint in the frozen main method. The recorded random seed is `0`.

All manuscript sections 3.1-3.5 must use this same frozen definition. If the definition changes, previously generated main-text results become invalid and must be recomputed.

## Claim Guardrails

Allowed:

- FragAnnotator is a fixed evidence-fusion candidate-ranking framework for LC-MS/MS small-molecule annotation.
- The manuscript CASMI result uses experimental spectra, candidate formulas, precursor mass consistency, common fragment or neutral-loss formula plausibility, and native SIRIUS formula evidence.
- Existing neural checkpoint results are audit or negative-control evidence unless a strict matched rerun proves otherwise.

Forbidden:

- Do not claim the current main method is a validated trained neural model.
- Do not claim trained neural FragAnnotator outperforms SOTA based on the existing checkpoint.
- Do not call CFM-ID-generated candidate spectra plus MS2DeepScore similarity a native MS2DeepScore benchmark.
- Do not place partial ICEBERG, MassFormer, or NEIMS results in a final main comparison table.
- Do not call PFAS locked-test independent validation until the independence audit proves it was not used for model, weight, component, router, gate, or configuration selection.
